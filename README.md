# Веб-аналитика подписок (Telegram Mini App)

FastAPI-сервер + одностраничный Vue-фронт. Переиспользует БД и модули бота —
**свой логики парсинга/кластеризации не дублирует**. Показывает по кнопке
«📊 Открыть полную аналитику» графики, круговую диаграмму и список подписок.

## Архитектура (важно понимать)

```
Telegram-бот (Python)                    Веб-аналитика (Python)
  main.py  ──пишет──►  MySQL  ◄──читает──  webapp/server.py (FastAPI)
                     statements                     │
                                                    └─► webapp/static/index.html (Vue+Chart.js)
```

Бот считает подписки и сохраняет в таблицу `statements`. Веб-апп только
**читает** уже посчитанное и рисует. Один источник правды — никакого
повторного анализа на другом языке.

## Файлы

- `webapp/server.py` — FastAPI-приложение (2 роута: `/` и `/api/analytics/{id}`).
- `webapp/tg_auth.py` — проверка подписи Telegram initData (HMAC от BOT_TOKEN).
- `webapp/analytics.py` — сборка данных для графиков из сохранённой выписки.
- `webapp/static/index.html` — фронт (Vue 3 + Chart.js с CDN, сборка не нужна).

## Установка

Из **корня проекта** (там, где `bot.py`, `database.py`):

```bash
pip install -r webapp/requirements-webapp.txt
```

`.env` — тот же, что у бота (нужны `BOT_TOKEN` и переменные `DB_*`).
База и таблица создаются автоматически (см. `database.init_db`).

## Запуск

```bash
# из корня проекта
uvicorn webapp.server:app --host 0.0.0.0 --port 8080
```

Telegram Mini App работает **только по HTTPS**. Для локальной разработки
подними туннель (например `cloudflared tunnel --url http://localhost:8080`
или `ngrok http 8080`) и используй выданный https-адрес.

## Подключение кнопки в боте

В `utils.py` кнопка сейчас ведёт на заглушку и **не передаёт номер выписки**.
Нужно два изменения.

1. Замени константу на свой https-адрес:

```python
WEBAPP_URL = "https://ВАШ-АДРЕС"   # адрес, на котором крутится server.py
```

2. Функция `make_subscriptions_keyboard` должна знать `statement_id` (он уже
   передаётся) и подставлять его в URL как `?sid=...`:

```python
builder.button(
    text="📊 Открыть полную аналитику",
    web_app=WebAppInfo(url=f"{WEBAPP_URL}/?sid={statement_id}"),
)
```

Фронт читает `sid` из URL, а `initData` берёт из Telegram.WebApp и шлёт
на сервер в заголовке `X-Init-Data`. Сервер проверяет подпись и что выписка
принадлежит именно этому пользователю (иначе 403).

## Безопасность

- Доступ к `/api/analytics/{id}` — только с валидным `initData` (подпись
  проверяется HMAC-SHA256 по алгоритму Telegram).
- Дополнительно сверяется `statements.user_id == telegram user id` —
  чужую выписку по подставленному `sid` открыть нельзя.
- `auth_date` старше суток отклоняется (защита от переигрывания).

## Ограничение CSV-режима

CSV-выписки (тестовый режим бота) сохраняются как «плоские» строки без
разбора дат и сумм — по замыслу они не проходят парсинг по колонкам.
Поэтому для CSV-выписок веб-графики будут **пустыми/скудными**: агрегатам
нечего считать без числовых дат и сумм. Веб-аналитика рассчитана на
PDF-путь. Если понадобятся графики и для CSV — надо парсить CSV в
`date/amount/desc` (тогда это уже не «сырой» режим).
